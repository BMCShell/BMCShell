# BMCShell Library 发布包与升级

## 发布包

Library 是可操作的业务库。框架的内部管理数据库独立维护，`bmc library` 只列出业务库。扩展通过登记的环境变量共享运行时信息。

```text
sbmc-library-cid@1.0.0.zip
├── bmc-package.json
├── README.md
├── help.json
├── changelog.json
└── library/
    └── cid.library.db
```

发布包中的 `*.library.db` 是 SQLite 安装模板，也可以随新版包发布新数据。包清单的 `data` 指向模板，`library` 声明结构版本、允许管理的表及稳定唯一键。唯一键应使用非敏感值。可用 `library.tables[].sensitiveFields` 登记冲突预览中需要遮蔽的列。SQLite 中的 `_bmcshell_library` 记录包 UUID、结构版本和数据版本。

```json
{
  "data": "library/cid.library.db",
  "library": {
    "schemaVersion": 1,
    "tables": [{"name": "records", "keys": ["key"]}],
    "lookup": {"table": "records", "value": "value"}
  }
}
```

| 版本 | 含义 |
| --- | --- |
| `version` | Library 包版本，随帮助、清单和数据库模板发布。 |
| `schemaVersion` | SQLite 表结构和数据接口的兼容版本。 |
| `dataVersion` | 模板中的发布数据版本。 |

## 安装和升级

使用 `bmc plugin install` 安装 Library 包，`bmc plugin upgrade` 从软件源升级。再次安装内容相同的本地 Library 版本时，保留工作库。卸载后安装同 UUID 的其他版本，以最后使用的工作库为本地数据进行合并。`bmc library <库名>` 使用业务库短名，显示包版本、数据库结构版本、数据版本及业务表。交互终端从信息页进入管理菜单，可按登记的键查看、新增、修改和删除记录。删除单条记录前需要确认。重定向输入时只显示信息。

工作库和发布模板各自保存。增量升级按稳定键比较本地工作库、上一个已安装发布包的模板和新版模板。相同记录按字段比较。

| 比较结果 | 处理 |
| --- | --- |
| 只有新版包修改 | 预览修改，采用新版包的值。 |
| 只有本地修改 | 保留本地值。 |
| 两边改为相同值 | 保留该值，视为无冲突。 |
| 两边改为不同值 | 列出记录、字段和脱敏后的双方值，交互选择本地值或新版包的值。无人值守保留本地值、记录并报告冲突，其余字段照常合并。 |
| 新版包包含新记录 | 预览新增，合并到工作库。 |
| 新版包缺少上一版的记录 | 列为拟删除并标明本地修改情况。经交互确认后删除，未确认时保留。 |
| 本地已经删除，新版包修改同一记录 | 报告冲突并保留本地删除。恢复该记录的交互规则待确认。 |

完成预览后，在暂存副本上应用数据变更并检查数据库完整性。成功后一起切换包版本、工作库和新版模板。保留此前版本的工作库和发布模板。审计记录区分升级、手动修改与插件修改，并记录包版本、涉及的记录与字段和采用的结果。审计保存标识和选择，字段内容留在工作库中。插件业务写入的接入方式另行确定。日常编辑与待写审计在当前 SQLite 工作库内一起提交，再续写到 `audit.jsonl`。备份时关闭相关进程，复制整个数据目录，使登记库、包、工作库和审计处在同一备份中。

## 结构变化

新版清单可用 `libraryMigrations` 声明从旧结构版本迁移的 SQL。迁移在工作库和基准模板的副本上进行，检查迁移结果和依赖工具声明的兼容范围，再合并新版数据。缺少兼容迁移时，报告结构冲突并保留旧版本及工作库。覆盖更新前保留备份，并要求二次确认。
